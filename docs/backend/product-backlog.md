### User Stories

> **Channel and Role Convention.** IceTrack operates via two applications, each tied to a specific role: the **web application** is the business owner channel (`OWNER_ROLE`) and the **mobile application** is the field technician channel (`TECHNICIAN_ROLE`). User stories describe functional behavior and do not include endpoints, HTTP methods, or HTTP status codes; those contracts are specified strictly within the Technical Stories. Hardware-driven stories indicate "IoT device" and those executed by the platform indicate "system". A service request originates in `PENDING` (unassigned); once assigned to a technician, it remains in `PENDING` until accepted (`ACCEPTED`), started (`IN_PROGRESS`), and the technical intervention is recorded (`COMPLETED`); it may transition to `CANCELED` from `PENDING` or `ACCEPTED`, and technician rejection reverts it back to `PENDING` (unassigned). Scope: refrigeration monitoring above 0 °C utilizing a DHT11 sensor probe (0 to 50 °C, accuracy of ±2 °C, and 1 °C resolution); freezers are not supported.

### Non-Functional Requirements (NFR)

| NFR ID | Category | Non-Functional Requirement Description | Verification |
| --- | --- | --- | --- |
| NFR-01 | Availability | The telemetry ingestion service must achieve 99.0% monthly availability, and the query API must reach 98.0%, measured against valid requests across 5-minute rolling windows. Cloud downtime must not impede local on-site excursion detection at the edge. | Endpoint availability logs evaluated during the release sprint. |
| NFR-02 | Response Time and Data Freshness | The web dashboard must reflect new readings in under 3 seconds at the 95th percentile, measured from the moment the platform receives the edge packet until the event reaches the browser. Total maximum end-to-end data freshness is 70 seconds, accounting for the 60-second gateway aggregation cycle. | Segmented latency tracking: ingestion-to-persistence, and persistence-to-streaming delivery. |
| NFR-03 | Scalability | The architecture must sustain at least 50 devices reporting every 10 seconds to the edge and 50 aggregated batches per minute forwarded to the cloud, without 95th-percentile ingestion latency exceeding 500 ms. The design must accommodate a ten-fold load increase through the addition of an ingestion queue, without requiring firmware or API contract changes. | Load testing on the telemetry endpoint using simulated IoT devices. |
| NFR-04 | Security and Encryption | All communications between the Edge gateway, RESTful API, web application, and mobile application must use HTTPS/TLS. The communication link between the ESP32 and the gateway must remain within the local on-site LAN without internet exposure. Each device must authenticate using a dedicated, revokable, and rotatable API key without requiring physical access; users authenticate via platform-issued JWTs. Field technicians operate the on-site gateway using an opaque, short-lived local grant issued per order and stored hashed; the gateway neither validates user JWTs nor holds signing secrets. | Certificate auditing and access verification using revoked credentials. |
| NFR-05 | Resilience and Fault Tolerance | The Edge gateway must persist every received reading to SQLite and retry delivery to the cloud using exponential backoff with jitter during network outages, maintaining a local buffer of at least 24 hours of telemetry data. The ESP32 maintains an in-memory buffer strictly for local network link drops. | 30-minute internet disconnection test verifying zero telemetry data loss. |
| NFR-06 | Usability and Accessibility | Web and mobile applications must follow responsive, mobile-first design and satisfy WCAG 2.1 Level AA standards, including proper ARIA attributes across web experiences. Critical temperature alerts must be identifiable through cues beyond color alone and understandable without specialized technical training. | Accessibility compliance audit and heuristic usability evaluations. |
| NFR-07 | Idempotency | All write operations originating from the Edge gateway or mobile offline queues must be idempotent via client-generated unique identifiers. Resubmitted payloads must neither create duplicate records nor trigger duplicate alert events. | Deliberate resubmission tests with previously synchronized batches and interventions. |
| NFR-08 | Edge Autonomy | The Edge gateway must independently detect thermal excursions, trigger hardware indicators, and store evidence without an active internet connection for at least 24 hours of isolated operation. Maintenance mode must be toggleable via the physical hardware button under the same disconnected conditions. | On-site operational testing with the WAN interface disabled. |
| NFR-09 | Internationalization | The landing page, web application, mobile application, and API responses must support English (en-US) and Latin American Spanish (es-419), with English as the default fallback. Notifications must be dispatched in the recipient's configured language. | Localization resource file audit and API header-based content negotiation tests. |
| NFR-10 | Observability and Traceability | Each reading must record capture timestamp and receipt timestamp independently, and each alert must reference its triggering reading. Every status transition of a service request must be logged with its author and timestamp. | End-to-end audit trail verification across alerts and complete service order lifecycles. |
